    1 · The whole system

    How the parts fit together

    Two processes talk over HTTP: the browser app and the dbx serve server. The server never sends file paths to the browser and never takes one from it; datasets are addressed by id. Every server part writes structured log lines, which are the only thing copied back from the host.

    2 · Three paths through the code

    What happens, step by step

    Indexing the data roots

    sequenceDiagram
  autonumber
  participant T as Catalog thread
    (catalog/service)
  participant S as scan()
    (catalog/crawl)
  participant W as walk()
    (catalog/crawl)
  participant P as Inspect pool
    (4 threads)
  participant I as inspect_path()
    (inspect/core)
  participant D as CatalogDB
    (catalog/db)
  Note over T: at start-up, every rescan_minutes,
    or POST /api/catalog/refresh
  T->>S: scan(roots, trigger)
  S->>D: start_scan · remove roots no longer configured
  loop each data root
    S->>D: stamps(root): what was indexed last time
    S->>W: walk(root)
    Note over W: os.scandir only · skips hidden + ignored
    symlinks must stay inside the root
    never descends into a zarr store
    W-->>S: candidates (.h5ad files, zarr stores)
    S->>P: _check(candidate) for each
    alt size/mtime stamp unchanged
      P-->>S: unchanged (no file read)
    else new or changed
      P->>I: fingerprint (structure only, no values)
      I-->>P: Fingerprint or error
      P-->>S: row: state, reason, summary, fingerprint
    end
    S->>D: upsert in batches · touch unchanged · remove unseen
  end
  S->>D: finish_scan(counts)
  Note over T,D: an unreadable root keeps its rows.
    Every step is logged with its timing.

    Opening a dataset and drawing it

    sequenceDiagram
  autonumber
  actor U as You
  participant FB as File browser
    (ui/FileBrowser)
  participant WS as Workspace
    (state/workspace)
  participant V as Embedding view hook
    (views/embedding)
  participant API as Dataset API
    (data/api)
  participant C as Catalog + cache
    (catalog/service · data/cache)
  participant R as Reader
    (data/reader)
  participant CW as Colour worker
  participant DK as deck.gl canvas
    (views/Canvas)
  U->>FB: select dataset, click Open
  FB->>API: GET /api/datasets/{id}/meta
  API->>C: get(id) · resolve(): path re-checked inside its root
  C->>R: open once (lazy read, or whole file if legacy and small)
  R-->>API: obs columns, categories, colours, embeddings
  API-->>FB: DatasetMeta (JSON)
  FB->>WS: addView(type, defaults from registry)
  WS->>V: ViewRunner runs the view's hook
  par positions
    V->>API: GET /obsm?key=X_umap&dims=0,1
    API->>R: read 2 columns → float32
    API-->>V: binary array (ETag, gzip)
  and colours
    V->>API: GET /obs?column=celltype
    API->>R: read 1 column → category codes
    API-->>V: binary array
  end
  V->>CW: codes + palette + hidden categories
  CW-->>V: RGBA per cell
  V->>DK: publish layers + bounds
  DK->>DK: fit the view to its cell, draw
  Note over V,DK: telemetry: dataset_meta, embedding_loaded,
    colours_computed, view_ready (ms)

    A log line, from event to file

    flowchart LR
  E["log.info(event, fields)
    or a library's log line
    or a Python warning"] --> C1["merge context
    request_id / job id"]
  C1 --> C2["add pid · role · build
    timestamp · level"]
  C2 --> P{"privacy level"}
  P -- debug --> F1["everything kept
    full traceback"]
  P -- standard --> F2["names kept in name fields
    quoted text + paths in messages → tokens
    messages cut at 300 chars"]
  P -- strict --> F3["every name field → salted token
    free text dropped
    exceptions: type + code lines only"]
  F1 & F2 & F3 --> J["JSON line"] --> FILE[("dbx-<role>-<pid>.jsonl
    rotating, pruned after retention_days")]
  T["timed('stage')"] -. "nested stage path,
    ms, RSS peak" .-> E
